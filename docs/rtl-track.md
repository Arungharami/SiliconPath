# Practice track: RTL → Simulation → Synthesis

Status: implemented November 5, 2026 (v1.6.0, unreleased). Content is original; faculty review pending.

## Problem
The Logic → CMOS track ends at transistor-level gates. Digital design work begins one level up, at register-transfer level (RTL): engineers describe hardware in an HDL, verify it by simulation, and synthesize it into gates. SiliconPath had no way to practice that workflow. The usual answer (install Icarus Verilog, GTKWave and Yosys) is a real barrier for beginners, and running learners' code on a server would add cost, accounts and an untrusted-code sandbox.

## Who it is for
- **Student who finished Logic → CMOS** and wants to write their first Verilog with immediate feedback.
- **Self-taught learner** who wants to try RTL before installing any tools, then move to real tools with a working project.
- **Instructor** who needs exercises whose grading is reproducible and whose claims are honest about what was and was not run.

## Architecture
| Layer | What runs | Where | Evidence label shown to learners |
| --- | --- | --- | --- |
| Feedback on learner code | `rtl-engine.js`: SiliconPath's interpreter for a defined Verilog-2005 subset | Browser | "Subset engine · your browser" |
| Validation of the engine | Icarus Verilog 13.0 and Yosys 0.70 on every reference, alternative, wrong and bugged design plus a 22-design semantics corpus | CI (`npm run test:rtl`) and maintainers' machines | — |
| Synthesis results | Real Yosys output for the track's reference full adder and the latch warning, committed in `rtl-synth.js` with the tool version | Generated by `npm run synth:rtl` | "Yosys output · generated by the project" |
| Learner's own tool run | Downloaded design, testbench, `run.sh` | Learner's computer | "Run locally with real tools" |

No backend, no WebAssembly, no new runtime dependency, no CSP change.

### The subset
ANSI-style ports; `wire`/`reg` up to 16 bits; sized and unsized literals; `assign`; `always @(*)` with blocking `=`; `always @(posedge clk)` with non-blocking `<=`; `if`/`else`; `case`/`default`; bit, part and variable-index selects; concatenation and replication; `~ ! & | ^ ~^ ~& ~| + - << >> == != < <= > >= && || ?:`; named-port module instances. Values follow the IEEE 1364-2005 width rules for unsigned expressions (operands widened to the context width before evaluation).

Rejected with an explanation: delays, `initial`, system tasks, x/z literals, `===`, multiplication/division, signed arithmetic, parameters, loops, functions, explicit sensitivity lists, positional instance ports, SystemVerilog keywords, implicit nets, latches, combinational loops and multiple drivers. Source is limited to 8,000 characters, 96 signals and 200 cycles.

Values are 2-state. A register that has never been assigned is "unknown" and anything computed from it is unknown (pessimistic; real simulators propagate x bit by bit). Checks treat unknown as wrong where the specification has a known value.

### Checking
- Combinational exercises: every input combination (up to 2¹² rows).
- Clocked exercises: a fixed cycle sequence designed to expose the likely bugs (reset priority, enable, wrap-around, terminal count with enable low). Unit tests confirm each exercise's wrong designs fail on that sequence.
- Test-vector exercises: every expected value must agree with the specification, and the vector set must make each of four bugged designs (mutants) produce a different output.
- Netlist exercise: answers are computed from the committed Yosys netlist text; the generator verifies those counts equal Yosys's own `stat` cell counts.
- Evidence: same model as Logic → CMOS. Records in `sp-rtl` are re-checked from the stored passing answer on load and import.

## Modules
1. **Introduction to RTL**: read a module (answers computed from the code); write `and3`.
2. **First hardware design**: 4-bit 2:1 multiplexer; half adder; full adder from exactly two half-adder instances.
3. **Hardware verification**: mutation-scored vectors for a multiplexer; fix a comparator from a failing-test report.
4. **Simulation and waveforms**: find the first cycle where a counter violates its specification; D flip-flop with enable and synchronous reset. Propagation delay is explained as text only: the engine is cycle-based.
5. **Logic synthesis**: remove a latch (real Yosys warning shown); read the real Yosys netlist of the full adder and estimate transistors with the Logic → CMOS gate costs.
6. **Mini project**: 4-bit counter with enable, synchronous reset and terminal count; cycle-by-cycle vectors that catch four bugs; ZIP bundle with design, testbench, `run.sh` and README.

## Decisions
1. **Own subset engine instead of a WebAssembly simulator.** No maintained WebAssembly build of Icarus Verilog was found (the one npm package found had one maintainer and 54 downloads a month); Verilator produces C++ that still needs a compiler. A small interpreter gives instant feedback with the existing CSP, and the Icarus cross-check turns "trust us" into a tested claim.
2. **No in-browser Yosys yet.** YoWASP Yosys (ISC licence) works in principle but ships about 69 MB of WebAssembly, needs `'wasm-unsafe-eval'` in the CSP, and its in-browser run was not verified. Showing real, version-stamped output for reference designs and sending learners to local tools for their own designs keeps every synthesis figure genuine.
3. **GPL tools are not redistributed.** Icarus Verilog and GTKWave (GPL-2.0) run only in CI and on learners' machines; the site links to their documentation.
4. **Mutation scoring for verification exercises.** It measures what matters (would these tests catch a bug?) rather than vector count, and it is exact for small designs.

The CI job installs Icarus Verilog and Yosys from Ubuntu packages, whose versions differ from the ones above. With a different Yosys version the committed netlist is verified functionally instead of byte for byte.

## Limitations
- The engine covers the subset only and is validated on the designs listed in the corpus and exercises, not on every possible learner design.
- No timing, delays, x/z semantics, power or area. Transistor counts are idealized static-CMOS estimates from Yosys `stat -tech cmos`, not results from a cell library.
- Synthesis output is shown for reference designs only; learners synthesize their own code locally.
- Nothing here is FPGA implementation, timing signoff or fabrication.
- `run.sh` needs a POSIX shell; Windows users need WSL or Git Bash (not yet tested).
- No screen-reader user testing; explanations await faculty review.

## Reproducing
```
npm run test:rtl     # requires iverilog and yosys on PATH
npm run synth:rtl    # regenerate rtl-synth.js after changing reference designs
```
